## KAD Enricher

Инструмент для получения списка дел с `kad.arbitr.ru`, постраничной обработки по судам, извлечения подробностей карточки дела и текста из связанных PDF (resultUrl). Результат инкрементально сохраняется в `results.json`.

### Требования
- Python 3.11+
- Windows PowerShell/CLI

Установите зависимости:
```bash
pip install -r requirements.txt
```

### Быстрый старт
1) Обновите куки (если нет доступа или ответ 451):
```bash
python main.py --mode update-cookies
```
Это откроет headless-браузер, соберёт куки и запишет их в `cookies.json`.

2) Запустите сбор дел и деталей:
```bash
python main.py
```
- Инкрементально сохраняет в `results.json` после каждого обработанного дела.
- Повторный запуск пропускает дела, у которых уже есть `details`.

Если видите баннер со статусом 451:
```
----------------------------------------
HTTP 451 from kad.arbitr.ru. Запустите обновление кук: python main.py --mode update-cookies
----------------------------------------
```
выполните обновление кук (шаг 1) и повторите запуск.

### Основные опции
- `--mode`:
  - `cases` (по умолчанию) — сбор дел, деталей и текстов из PDF.
  - `update-cookies` — обновление cookies через браузер.
- `--cookies-file` — путь к файлу куков (по умолчанию `cookies.json`).
- `--out` — путь к результирующему JSON (по умолчанию `results.json`).
- `--start-page`, `--end-page` — диапазон страниц для пагинации (по умолчанию 1..9999).
- `--courts-file` — путь к файлу со списком судов (по умолчанию `courts.json`).

### Формат courts.json
Файл содержит массив объектов с полями:
```json
[
  { "code": "VAS", "name": "Высший Арбитражный Суд РФ" },
  { "code": "MSK", "name": "АС города Москвы" }
]
```
Коды соответствуют значениям value из селекта `Courts` на сайте.

### Что делает каждая часть проекта
- `main.py`
  - Точка входа. Разбирает аргументы, настраивает логирование.
  - В режиме `update-cookies` — запускает браузер и сохраняет куки.
  - В режиме `cases` —
    - читает текущий `results.json` и строит индекс по `caseUrl`;
    - итерируется по судам из `courts.json` и по страницам;
    - для каждой страницы вызывает получение списков дел;
    - для каждого дела открывает карточку, парсит детали и, если есть `resultUrl`, скачивает PDF и извлекает текст в поле `result`;
    - после каждого дела инкрементально обновляет `results.json`.

- `services/cases.py`
  - `build_cases_request(page, count, courts)` — собирает заголовки, payload (включая фильтр по судам) и прокси для POST `https://kad.arbitr.ru/Kad/SearchInstances`.
  - `fetch_cases_html(url, cookies, headers, payload, proxies)` — отправляет запрос на список дел. При HTTP 451 печатает баннер с инструкцией и завершает программу.
  - `parse_cases(html)` — парсит HTML списка дел: номер, дата, суд, судья, стороны, ссылка карточки.
  - `parse_pages_count(html)` — вынимает общее число страниц из `<input id="documentsPagesCount" ...>`.
  - `get_cases(cookies_file, page, count, courts)` — возвращает список дел, cookies/headers/proxies и `pages_count`.

- `services/case_details.py`
  - `fetch_case_html(case_url, cookies, headers, proxies)` — скачивает HTML карточки дела. При HTTP 451 печатает баннер и завершает программу.
  - `parse_case_details(html)` — парсит длительность заседания, хронологию (instance/date/court/resultUrl и т.д.), статью/категорию, третьих/прочих лиц.
  - `fetch_pdf_text(url, cookies, proxies, headers)` — пытается получить PDF, обойти антибот и извлечь текст (через `pdfminer`). Возвращает текст или `None`.

- `services/cookies.py`
  - `get_cookies_via_browser(start_url, proxy, user_agent)` — поднимает Playwright Chromium с прокси/UA, открывает сайт, кликает "Найти", возвращает куки.
  - `save_cookies(file_path, data)` / `load_cookies(file_path)` — сохранение/чтение кук в/из JSON.

- `courts.json`
  - Список судов и человекочитаемых названий. Используется `main.py` для перебора судов и фильтрации запроса.

- `results.json`
  - Результирующий файл. Структура элементов включает поля списка дел и поле `details`, содержащее:
    - `duration`, `article`, `thirdParties`, `otherParties`;
    - `chronology`: массив событий; элементы могут содержать `resultUrl` и извлечённый `result` (текст из PDF).

- `cookies.json`
  - Файл кук, используемый для авторизованного запроса к сайту.


### Логи и поведение
- Логи уровня INFO:
  - выбранный режим, суд, номер страницы;
  - обнаруженное число страниц;
  - прогресс по делам: `[p{page}] [{i}/{N}]` при получении и разборе деталей;
  - пропуски уже обработанных дел.
- При HTTP 451 программа печатает баннер и завершает работу с предложением обновить куки.

### Советы по эксплуатации
- Если сайт начал чаще отдавать 451 — чаще обновляйте куки (или меняйте прокси/UA).
- При прерывании процесса перезапуск продолжит с места остановки — уже обработанные дела со встроенными `details` будут пропущены.
- Для ускорения можно ограничивать `--end-page` и список судов в `courts.json`.
